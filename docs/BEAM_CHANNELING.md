# 빔 무제한 홀드

## 목표와 범위

공격 시작 노드에 직접 연결한 빔을 버튼 유지 중 시간 제한 없이 유지하고, 종료 시점부터 0.5초 재시전 쿨타임을 적용한다. 기존 클릭 유지 입력, 빔 경로·모듈·피해·이벤트 처리는 재사용한다.

## 동작

- 직접 시전 홀드는 최대 3초 제한을 사용하지 않는다. 버튼 해제 또는 유지 비용 부족 시 즉시 종료한다.
- 직접 빔의 유지 결제는 빔 행동의 초기 실행 비용(빔 노드와 선결제 onHit 전력)을 `TickInterval / MinimumLifetime` 비율로 나눠 각 피해 주기마다 낸다. 기본값은 0.1초 주기와 0.5초 초기 구간이므로 초기 실행 비용의 1/5씩 추가 결제하며, 종료 시 초기 비용을 환급하지 않는다.
- 공격 시작에 직접 연결한 빔 주문에는 일반 RAM·실행 시간 쿨타임을 선적용하지 않는다. 빔 채널 종료 시 슬롯의 전용 쿨타임을 시작한다.
- 다중 빔은 행동별 공유 채널을 한 번만 결제·종료한다. 같은 주문에 여러 직접 빔 행동이 있으면 마지막 빔 종료 시점이 쿨타임 기준이다.
- 이벤트·호출·반복으로 생성되어 홀드 입력이 없는 빔은 기존처럼 초기 결제 구간만 유지한다. 다른 행동의 쿨타임은 바꾸지 않는다.
- 종료 후 쿨타임 중 새 클릭을 예약할 수 있으나 버튼을 놓으면 예약을 취소한다. 일시정지·장착 변경·전투 종료는 기존 취소 경로를 따른다.
- 유지 중 HUD에는 남은 실행 시간 대신 빔 유지 상태를 표시한다. 직접 홀드 빔의 총 유지 비용은 상한 없음으로 계산한다.

## 설정과 연결

`balance.json`의 `_sim._beamCooldownSeconds`에서 종료 후 쿨타임을 관리하며 현재 값은 0.5초다. `form.beam._stats._lifetime`은 시간 상한이 없음을 나타내는 0이다. `form.beam`의 초기 결제 구간과 피해 주기를 사용하고, 직접 빔의 초기 실행 비용은 유지 결제의 기준으로 사용한다. 추가 Inspector 연결은 없다.

Unity 플레이는 미검증이다. 이 환경의 Unity 배치 실행은 프로젝트 시작 단계에서 종료되어 실행 검증을 완료하지 못했다. 시험 도크에서 공격 시작에 빔을 직접 연결해 3초 이상 유지한 뒤 버튼을 놓고, 0.5초 전후 재클릭·전력 고갈·다중·공전·유도·탭 전환을 확인해야 한다.
