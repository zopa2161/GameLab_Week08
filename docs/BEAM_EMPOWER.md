# 빔 전용 과충전 모드

## 목표와 범위

과충전 모드(`mod.beamEmpower`)가 연결된 빔은 연속 채널링 2초부터 피해·마나 유지 비용·빔 폭이 점진적으로 증가하고, 총 5초에 최대치에 도달한다. 충전량은 빔의 실제 적중 폭과 부드러운 발광에도 반영한다.

## 동작

- `behavior.beam` 전용이며 다른 행동과 프리셋 호출에는 적용하지 않는다.
- 총 채널링 2초까지는 모든 충전 배율이 1이다. 2~5초에는 진행률 `(채널링 시간 - 2) / 3`에 따라 각 배율을 `1 + (최대 배율 - 1) × 진행률`로 선형 보간하고, 5초 이후에는 최대치를 유지한다.
- 최대 배율은 다음과 같다.

| 등급 | 피해 | 마나 유지 비용 | 빔 폭 |
| --- | --- | --- | --- |
| C | 2배 | 2배 | 3배 |
| B | 2.67배 | 2.67배 | 4배 |
| A | 3.33배 | 3.33배 | 5배 |
| S | 4배 | 4배 | 6배 |

- S등급은 총 3.5초에 피해 2.5배·마나 2.5배·폭 3.5배, 총 5초에 피해 4배·마나 4배·폭 6배다.
- 마나는 채널의 기존 원본 구간 비용에서 매 결제 틱의 진행률로 산정한다. 직전 충전 비용에 다시 배율을 곱하지 않으며, 다른 자원 비용은 유지한다. 최초 시전과 2초 이전에는 추가 충전 비용이 없다.
- 과충전의 고정 등급별 에너지 배율은 모두 1로 두어 최대 마나 4배에 별도의 과충전 고정 배율을 중복 적용하지 않는다. 다른 모드와 기존 시전 구조의 비용은 원래대로 계산한다.
- 크기 증가는 빔의 가로 폭에 적용하며 실제 적중 판정·표시·유도 접촉 폭이 같은 값을 사용한다. 경로 길이·공전 반경·피해 주기·OnHit 발생 규칙은 유지한다.
- 벽 통과는 충전 전후 동일하다. 다중 빔은 같은 공유 채널의 시간을 기준으로 충전하며 유지 비용도 채널당 한 번 결제한다.
- 공격 해제·마나 부족·장착 변경·전투 종료 등 기존 취소 경로가 채널을 종료하면 강화가 해제된다. 재시전은 0초부터 시작한다.
- 월드 메시와 UI 경기장 모두 충전량에 따라 밝은 중심색과 투명한 가장자리의 발광을 강화한다. 별도의 테두리 선 없이 약하고 느린 맥동을 유지하며 Bloom 설정을 요구하지 않는다.
- 빔 본체와 발광은 이웃 경로 구간이 꼭짓점을 공유하는 연속 띠로 그린다. 굵은 유도·공전 빔의 구간 사이 틈과 중복 발광을 방지하고, 닫힌 공전 경로의 첫·끝 폭 방향도 일치시킨다.

## 설정과 연결

- `tables/runes.json`: 빔 전용 과충전 모드, RAM 1, 작업대 해금 비용 50.
- `tables/elite_modifier_drops.json`: `_gradeValues`는 최대 피해, `_beamEmpowerManaMultByGrade`는 최대 마나, `_beamEmpowerSizeMultByGrade`는 최대 빔 폭이다. 기존 보상·드롭 테이블 등록을 유지한다.
- `BeamEmpowerModifierRules.CHANNEL_SECONDS`는 강화 시작 2초, `MAX_CHANNEL_SECONDS`는 총 채널링 기준 최대 충전 5초다.
- `SpellAction`은 등급별 최대 배율을 보관하고 `BeamChannel`은 공유 채널 시작 틱으로 진행률을 계산한다. 비용에는 현재 결제 틱을, 피해·폭·발광에는 현재 채널 관측 틱을 사용한다.
- `SpellInspectorPresenter`, `strings.ko.json`, 테이블 편집기에 시간 기준과 세 최대 배율을 연결한다.
- 추가 Inspector 연결은 없다.

Unity 플레이는 미검증이다. 시험 도크에서 빔에 과충전을 연결하고 2초 전후 변화 시작, 3.5초 중간 배율, 5초 이후 상한을 확인한다. C/B/A/S 각각의 최대 배율, 증가한 빔 가장자리의 적중, 마나 부족 즉시 종료, 재시전 초기화, 다중·유도·공전·탭 전환도 확인한다. 화면 코드는 프로젝트의 소스·참조 목록을 사용해 직접 컴파일했다.
