# Rune Code 인크리멘탈 PoC

로그 기록·자동 전송·온라인 수집·분석의 전체 흐름은 [로그 시스템 설명서](LOG_SYSTEM.md)를 참고한다.

하나의 마법을 룬 노드로 연결하고 확장하는 Unity 게임이다. 5×5 방 크기의 넓은 맵에서 직접 이동·조준하며 사방에서 나타나는 편성된 적을 모두 처치한 뒤, 처치 보상 RAM으로 설계와 완드를 강화한다. Unity 6000.3.22f1 / Windows x64를 사용한다.

## 실행

`Builds/RuneCodePoC-ManualMods-Windows.zip`을 모두 압축 해제한 뒤 `RuneCodePoC.exe`를 실행한다. 실행 파일과 `_Data`, `UnityPlayer.dll`, `MonoBleedingEdge`를 함께 유지한다. 이전 빌드와 ZIP은 보존한다.

Editor에서는 `Assets/Scenes/Boot.unity`를 열고 Play한다.

## 플레이 흐름

1. 작업실에서 시작 마법 파이어 볼트의 노드를 편집하고 시험 도크에서 확인한다.
2. 출격 탭에서 해금된 스테이지를 선택한다. 5·10스테이지는 제한시간(45·60초)이 있는 보스 스테이지다.
3. WASD로 이동하고 마우스로 조준한다. 카메라가 플레이어를 따라가며 맵 끝에서 멈춘다. 포인터가 게임 화면 안에 있으면 조준 방향으로 현재 마법을 연속 시전한다. Space는 대시, Esc는 일시정지다. 점멸 노드에 의한 이동도 유지된다.
4. 편성된 적이 모두 나온 뒤 맵의 적을 전부 처치하면 클리어다. 시간만 지나서는 클리어되지 않으며 화면 위쪽에 남은 적 수(아직 나오지 않은 수 + 살아 있는 수)가 표시된다. 클리어하면 처치 RAM 100%를 정산한다. 사망·중단·보스 제한시간 초과는 처치 RAM의 70%를 반올림해 지급한다.
5. 결과의 `마법 강화`로 같은 설계를 계속 확장한다. `같은 스테이지 재도전`으로 반복 수급할 수 있다. 첫 완주 시 노이즈 룬이 해금된다.

마법의 피해·형태·속성·다중 발사·흐름은 노드를 연결하여 바꾼다. 별도의 공격력 구매나 마법 슬롯 구매는 없다. 일반 스테이지에서는 적응 감쇠를 사용하지 않으며, 시험 도크의 적응 옵션은 유지한다.

## RAM과 별도 강화

**보유 RAM**은 적 처치로 얻는 구매 재화다. **노드 RAM / 용량**은 현재 그래프의 크기 제한으로, 배치할 때 보유 재화를 차감하지 않는다.

| 강화 | 시작 비용 | 단계당 효과 |
|---|---:|---|
| RAM 용량 | 12 RAM | 용량 +2 (기본 6) |
| 에너지 | 15 RAM | 최대 EN +10, 초당 회복 +1 (기본 EN100 / 회복15) |
| 전투시간 | 18 RAM | +5초 (기본30초, 최대120초). 전투가 전부 처치로 끝나도록 바뀌어 현재 전투에는 효과가 없다 |

다음 가격은 `ceil(시작 비용 × 1.22^현재 단계)`다. 용량과 에너지는 각각 최대100단계, 전투시간은18단계다. 미해금 룬은 벤치에서 RAM으로 해금한다. 용량 초과, 미해금 룬 또는 잘못된 연결이 있으면 출격할 수 없다. 최대 예상 마나 비용이 최대 에너지를 넘으면 경고만 표시하고, 전투 중 마나가 부족한 노드에서 그 경로만 중단된다. 노드 강화가 성장의 중심이며 별도 강화는 큰 설계를 사용할 자원과 전투 길이를 제공한다.

## 사거리·크기·속도 커스텀

벤치에서 사거리·속도 수식을 각각20 RAM, 기존 확장 수식을30 RAM으로 해금하고, 해당 노드의 `mod`를 형태 노드의 `mod`에 연결한다. 노드를 선택하면 인스펙터에서 배율을 입력하거나 −/+로0.1씩 조절할 수 있다. 범위는0.5~3배이며 기본1.5배다.

| 수식 | 조절 효과 |
|---|---|
| 사거리 | 볼트의 비행 거리, 버스트·존의 생성 거리, 오비트의 궤도 거리 |
| 확장 / 면적 | 일반 형상의 반경·폭·길이에 면적 배율의 제곱근을 적용한다. 폭발은 파동 속도·두께를 함께 조정하고, 고정 길이 빔은 폭만 면적 배율로 늘린다. 공전 궤도 반경과 기존 피해 배율은 유지한다 |
| 속도 | 볼트 이동 속도, 오비트 회전 속도. 볼트 비행 거리는 유지하며 비행 시간이 바뀜 |

예를 들어 기본 볼트의 속도는480px/s, 비행 거리는672px다. 속도2배는960px/s로 움직이지만672px에서 끝난다. 사거리2배를 함께 연결하면1344px까지 비행한다. 벽이나 적에 닿으면 먼저 끝날 수 있다. 확장 면적2배는 충돌 반경6→약8.49px이며 실제 표시와 충돌 판정에 함께 적용된다. C/B/A/S의 면적 배율은1.5/2/2.7/4이며, 일반 형상의 길이 배율은 각각 약1.225/1.414/1.643/2다. 면적으로 계산하는 Shape 비용·실행 시간도 조정된 크기를 사용한다.

형태 노드를 선택하면 적용된 사거리·충돌 반경·속도를 확인할 수 있다. 즉시 발생하는 버스트와 고정된 존에 속도를 연결하면 효과 없음 경고W2가 나온다. 기존 형태당3개 수식·속성 연결 제한은 유지한다. 기존 확장 노드에 배율이 없으면 이전과 같은1.5배로 해석한다. 저장과 RC1 공유는 배율을 보존한다.

## 노드 편집과 시험

시험 도크는 현재/최대 전력을 막대와 숫자로 표시한다. 더미 수량 버튼은 1→2→3→4→5→1마리로 순환하며 같은 종류의 더미를 플레이어 앞쪽에 일렬로 배치한다. 더미 체력은 각각10000이며 피해 숫자는 계속 표시한다. 수량을 바꾸면 시험을 초기화하고, 일반 리셋·탭 재진입은 선택 수량을 유지한다.

| 동작 | 조작 |
|---|---|
| 배치·연결 | 팔레트 클릭/드래그, 노드 이동, 포트 드래그 연결 |
| 화면·선택 | 중간 버튼 또는 빈 곳 우클릭 드래그, 휠 확대, Shift 다중 선택, 빈 곳 영역 선택 |
| 삭제·검색 | Del/Backspace 노드 삭제, 연결선 우클릭 삭제, 빈 곳 더블클릭 검색 |
| 복사·편집 | Ctrl+C/V 노드 복사·붙여넣기, Ctrl+D 노드 복제, Ctrl+Z/Y 되돌리기·복구, Ctrl+S 저장 |
| 시험 도크 | 클릭 또는 시험 버튼 시전, 자동 시전·적응·배속 옵션, R 초기화 |

`exec`는 실행 흐름, `mod`는 효과(Modifier) 부착이다. 속성은 Shape·Apply 노드의 드롭다운으로 고른다. 공유 RC1 가져오기는 현재 마법 ID를 유지하며 설계를 교체하고, 실행 취소로 복구할 수 있다. 전투 중에는 그래프 편집이 잠긴다. 과도한 중첩 반복은 컴파일 오류 E8로 제한하며 실행 예약·틱당 처리량에도 상한이 있다.

## 마법 문법

규범은 「마법 비주얼 스크립팅 — 문법 구현 백서」이며 구현 현황은 `docs/GRAMMAR_STATUS.md`에 정리한다.

```text
Trigger → [FlowControl...] → Shape(Element) → Behavior
Trigger → [FlowControl...] → Apply(Element)
Trigger → [FlowControl...] → 프리셋 호출
```

- Shape: 구형·사각·부채꼴. Behavior: 발사·폭발·공전·잔류·적용. 효과(Modifier)는 Behavior·프리셋 호출에 붙인다.
- onHit 직렬 체인의 전력은 최초 행동이 시작될 때 `(최초 행동과 onHit 후속 노드의 전력 합계) × 1.5^(연결된 행동 노드 수 - 1)`로 선결제한다. 다중·관통·연속으로 후속 행동이 여러 번 발동해도 전력을 다시 차감하지 않는다. 전력이 부족하면 첫 행동을 생성하지 않고 해당 경로를 중단한다. 소멸·첫 적중 또는 소멸 이벤트와 빔 유지비는 별도로 결제한다.
- 적에게 부여한 화상은 기본3초 동안0.5초마다 점화 공격 피해의10%를 준다. 재점화하면 기존보다 더 큰 점화 피해일 때만 화상 피해와 출처를 바꾸고, 지속시간은 갱신하며 기존 틱 일정은 유지한다. 비율은 `balance.json`의 `_combat._burnDamageRatio`로 조정하며, 공격 수식·관통 감쇠 뒤의 피해를 기준으로 전투 공통 피해 보정은 각 틱에 한 번만 적용한다. 자기 적용 화상은 기존 고정 DPS를 유지한다.
- 이전 저장 그래프의 지원이 끝난 연결(폭발·적용의 이벤트, 조건의 거짓 출력, 이전 `onComplete`)은 보존되지만 실행되지 않고 경고가 표시된다.

## 저장과 이전 진행

`Application.persistentDataPath/runecode.save.v2.json`에 단일 마법, RAM, 성장, 해금, 스테이지와 설정을 저장한다. Windows 기본 경로는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\w06-test2`다.

v2가 없으면 기존 v1을 읽어 A 슬롯 마법을 활성 설계로 이전한다. 다른 설계는 저장 내부에 보존하고 기존 v1 원본 파일은 수정하지 않는다. A가 비어 있으면 첫 설계를 사용한다. 기존 용량·에너지·체력 성장과 해금·설정을 유지하고, 구매한 C 슬롯은120 RAM으로 환불한다. 이전 섹터 클리어 기록은 스테이지1 완주 기록으로 이전한다. 새 UI에는 마법 보관함·슬롯 선택을 표시하지 않는다.

설정 화면에서 진행을 초기화할 수 있다. `.backup`과 `.invalid-backup`은 같은 저장 폴더에 보관한다. F8은 최대500건의 로컬 기록을 출력한다. 실행 인수 `-debug`는 RAM 지급·룬 해금·무적·적 소환 도구를 표시한다.

## 시뮬레이션 CLI

프로젝트 루트의 PowerShell에서 새 Windows 빌드를 이용한다.

```powershell
.\tools\sim.ps1 -Spell firebolt -Scenario incremental -Ticks 6000 -Seed 1 -Stage 1 -Output Builds/incremental-sim.json
.\tools\sim.ps1 -Spell triplefire -Scenario incremental -Ticks 6000 -Stage 2 -CapacityLevel 1 -EnergyLevel 1
.\tools\sim.ps1 -Spell firebolt -Scenario dummy_line -Ticks 600 -Seed 1
```

`incremental`은 비교용 자동 조준 입력(이동 없음)과 게임의 기본 능력치를 사용하며 클리어·사망·보스 시간 초과 시 멈춘다. `-Duration`은 더 이상 쓰이지 않으며 0이 아니면 경고만 남긴다. 템플릿 `firebolt`, `shockwave`, `triplefire` 또는 마법 JSON 파일을 지정한다. 비교용 도크 시나리오 `dummy_single`, `dummy_line`, `dummy_swarm`, `aegis`, `adapt_loop`는 기존 RAM24 / EN150 조건을 유지한다. CLI의 모든 룬은 해금된 조건으로 컴파일한다.

JSON에는 피해, DPS, 에너지 사용량, 실행 횟수·시간, 상태 해시, 스테이지, 보스 제한시간·남은 시간, 편성 총수·남은 적 수, 종료 상태, 처치·획득·정산 RAM과 실행 상한으로 생략된 명령 수가 담긴다. CLI는 사용자 저장을 변경하지 않는다.

## 데이터와 검증

`Assets/RuneCode/Resources/RuneCode/stages.json`은 맵 크기·스폰 설정·성장 계수·적 보상과 연속 미션의 스테이지·라운드·웨이브 편성을, `formations.json`은 스폰 진형(흩뿌림·포위·일렬)의 기본값을, `balance.json`은 성장 가격·증가량·실행 상한을 관리한다. 게임 규칙은 기존 Core, 표시와 플레이어 입력 연결은 UI(미션 전투는 `UI/Mission/World`의 월드 오브젝트와 미션 카메라), 저장은 Save에서 처리한다.

검증 이력은 `docs/history/PROGRESS.md`, 변경 결정은 `docs/decisions/DECISIONS.md`에 기록한다. AGENTS.md에 따라 Git CLI·커밋·push와 테스트 코드·자산 추가는 수행하지 않는다.
