# 보스 패턴별 사용·플레이어 피해 로그

## 목표와 범위
현재 히드라, 레골라스, 헥사, 거버너, 미니 거버너의 패턴 사용 횟수와 플레이어에게 준 실제 피해를 보스·스테이지·라운드별로 비교한다.

## 동작과 연결
기존 SimulationStats가 enemy_id·스테이지·라운드·패턴 ID별 누계를 소유한다. 패턴 시작 시 use_count를 증가시키고 실제 피격 직후 damage_hp·shield_absorbed·hit_count를 누적한다. 탄환·예약 연사는 생성 당시 패턴을 보존하고 히드라 잔류 독·파동은 원래 패턴으로 기록한다. 소환물 피해는 원래 적 통계를 유지하면서 소환 보스의 패턴 분석에도 별도로 귀속한다. 중복 합산하지 않고 두 분석의 관점으로 구분한다.

round_break_start와 combat_end의 기존 data.enemy_stats 안에 보스 개체별 boss_patterns 배열로 추가한다. 전투 종료 스냅샷 공급자를 재사용하므로 정상 타이틀 복귀·앱 종료에도 같은 누계를 수집한다. 강제 종료는 마지막 저장 경계 이후 누계를 보장하지 않는다. CSV 열 추가나 Inspector 설정은 없다.

## 로그 해석
세션·전투·보스 개체·스테이지·라운드·패턴 ID별 최신 누계로 해석한다. 반복 스냅샷을 합산하지 않는다. 신규 로컬 분석기의 적 유형 분석과 신규 웹 리포트의 보스 패턴 분석 탭에서 전체·스테이지별·라운드별 사용·HP 피해·보호막 피해·유효 피격 및 참가자 상세를 제공한다.

사용 횟수는 성공 명중이나 탄환 수가 아닌 시작 횟수다. 헥사 복합 패턴은 선택된 두 공격의 순서를 포함한 ID로 한 번 센다. 히드라 반복 도약은 하나의 도약·파동 패턴 시작으로 센다. 레골라스의 벽 탈출 연속 도약은 각 도약·범위 공격 시작을 센다. 거버너 장판은 장판 하나 생성당 한 번이다. 피해는 적용 시점의 스테이지·라운드로 귀속한다.

## 완료 기준
각 보스의 시작 지점과 직접 공격·지연 공격·소환 피해가 연결되고 전투/라운드 경계에서 JSON 누계가 유지되어야 한다. 기존 피해·무적·이동·소환 규칙은 바꾸지 않는다. 새 빌드에서 기존 전송 경로로 패턴 누계를 수집할 수 있어야 한다. 수신된 실제 로그의 패턴 누계와 반복 스냅샷 중복 제거, 온라인 화면의 라운드별 피해 전환을 확인했다.
