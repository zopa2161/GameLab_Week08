# 런 종료 화면

## 목표와 범위

런 종료 후 사용한 빌드와 해당 런의 전투 기록을 먼저 살펴볼 수 있도록 기존 RunResultPopup을 개편한다. 기존 클리어·실패 판정과 타이틀 복귀 흐름을 유지한다.

## 화면과 동작

- 왼쪽: 마지막 빌드 이름, 노드·연결선·속성·모디 슬롯을 작업실과 같은 표현으로 표시한다. RAM·노드 수·연결 수를 함께 표시한다.
- 빌드는 읽기 전용이다. 드래그 이동, 휠 확대·축소, 전체 보기만 지원한다. 긴 빌드도 처음에는 전체가 들어오도록 축소한다.
- 오른쪽: 적에게 가한 피해, 처치 수, 받은 HP 피해, 보호막 흡수, 평균 초당 피해, 소모 전력, 대시 횟수를 표시한다.
- 상단: 런 종료/시간 초과/런 클리어 제목, 도달 스테이지·라운드, 시뮬레이션 전투 시간을 표시한다.
- 타이틀 복귀는 오른쪽 아래의 작은 버튼으로 제공한다. Esc로 결과를 닫지 않는다.

## 데이터와 연결

MissionRun은 EndRun이 진행과 편집 데이터를 초기화하기 전에 결과 그래프와 참조 라이브러리를 깊은 복사로 보관한다. 결과 화면은 해당 복사본과 마지막 CompiledSpell, 종료한 RuneSimulation의 실제 누계를 사용한다. 이전 런이나 새로 초기화된 시작 빌드를 표시하지 않는다.

평균 초당 피해는 TotalDamage / simulation.Time이다. 시간은 전투가 진행된 시간이며 작업실·일시정지 시간은 포함하지 않는다. 전투 시간이 0이면 평균은 0으로 표시한다. 피해량은 기존 실제 피해 누계를 사용하며 임의 점수나 최대 단일 피해량을 만들지 않는다.

## 설정과 적용

기존 RunResultPopup Prefab의 루트 GUID를 유지한다. 공통 패널·버튼·글꼴·그래프 스타일과 GraphMeshPainter·GraphNodeLabels를 재사용한다. RuneCode/UI/Rebuild Run Result Popup 메뉴는 해당 Prefab만 다시 베이크하고 필요한 Inspector 참조를 연결한다.

## 완료 기준

- 저장 초기화 이후에도 마지막 빌드와 실제 누계가 유지된다.
- 빌드 영역에서 입력해도 저장 데이터와 노드 좌표가 바뀌지 않는다.
- 빌드와 수치가 겹치지 않고 타이틀 버튼이 우측 하단에 위치한다.
- 재사용 시 빌드·레이블·버튼 리스너가 중복되지 않는다.
- Prefab의 Missing Script와 필수 참조 누락이 없다.
- 클리어/실패 제목과 기존 타이틀 복귀 동작이 보존된다.

## 확인 상태

런타임과 Editor 배치 코드는 기존 Unity 참조와 Unity 가져오기를 통과했다. 실행 중인 Unity에서 Prefab을 베이크하고 기본 마법으로 전투 시뮬레이션을 진행한 뒤 실제 누계를 바인딩해 1920×1080 화면을 렌더링했다. Missing Script는 0개이며 필요한 Inspector 참조를 연결했다. 작업실 편집 동작, 플레이어 조작으로 사망한 뒤 결과 팝업 열기와 타이틀 복귀의 전체 플레이 흐름은 별도 확인이 남아 있다.
